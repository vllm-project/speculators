# LiLiCorr full-scale run: Qwen3.8-27B drafter on OpenPerfectBlend-Qwen38-27B-regenerated

Exact commands to reproduce the full training run launched 2026-10-22 18:16 UTC (later paused at `epoch0_step9260` for an acceptance probe; resumes losslessly — see [Resume after a pause](#6-resume-after-a-pause)).

Everything below was executed on the dev container described in the repo's `CLAUDE.md`: 8x A100-80GB, repos under `/workspace`, per-repo venvs. Paths are the literal paths used on that pod — substitute your checkout location for `/workspace/speculators/.claude/worktrees/lilicorr-minimal` (any checkout of branch `lilicorr` at the commit containing this file is equivalent).

Serving/probing additionally needs the vLLM side: branch `lilicorr-speculators-config` (commit `2bf157bd17`, fork `MeganEFlynn/vllm`) checked out at `/workspace/vllm/.claude/worktrees/lilicorr-speculators-config`. Training itself does not need it — only the acceptance probe does.

## 0. Repos and branches

Two repos are involved, and the run scripts hardcode worktree paths under each. Reproduce that exact layout with:

```bash
# speculators: training code (branch lilicorr = the commit containing this file)
git clone https://github.com/vllm-project/speculators.git /workspace/speculators
mkdir -p /workspace/speculators/.claude/worktrees
git -C /workspace/speculators worktree add .claude/worktrees/lilicorr-minimal lilicorr

# vllm: serving-side config translator, needed only for the probe/serving
# (branch lilicorr-speculators-config, tip 2bf157bd17, lives on the fork)
git clone https://github.com/MeganEFlynn/vllm.git /workspace/vllm
mkdir -p /workspace/vllm/.claude/worktrees
git -C /workspace/vllm worktree add .claude/worktrees/lilicorr-speculators-config lilicorr-speculators-config
```

A plain checkout of either branch (no worktree) works too — adjust `PYTHONPATH` and the `cd` in the commands below to point at it. The per-repo venvs (`/workspace/<repo>/.venv`, created with `--system-site-packages` so they inherit torch/CUDA from the base image — see `CLAUDE.md`) are provisioned by the dev container; the scripts set `PYTHONPATH` to the worktrees, which takes precedence over any installed copy.

## 3. Build the training dataset (arrow)

Run the four scripts in this directory with the speculators venv python (needs pyarrow + numpy). They are the scripts that produced the run's data, committed as-run modulo mechanical lint normalization (ruff formatting, merged `with` statements, `max()`/`min()` collapse — no behavioral changes).

```bash
cd <this directory>   # scripts hardcode /tmp/lilicorr_check/qwen38-perfectblend paths
/workspace/speculators/.venv/bin/python run_stage1.py        # stage 1: 48 byte-range workers
/workspace/speculators/.venv/bin/python write_final_full.py \
    /tmp/lilicorr_check/qwen38-perfectblend/datafull          # stage 2: final save_to_disk layout
/workspace/speculators/.venv/bin/python scan_bad_full.py      # vocab-bounds scan (expect 0 bad rows)
```

Stage 1 converts the uncompressed jsonl in parallel: worker `i` seeks to `size*i//48`, skips the first partial line, and reads lines while their start offset `<= size*(i+1)//48`, so every line is processed exactly once. Stage 2 hand-writes the `save_to_disk` layout because the ~4.3B-token `list<int64>` table exceeds the 2.15B-element `combine_chunks` limit of `datasets`.

Stage 1's driver aggregates per-worker stats; if an aggregate looks wrong (e.g. a summed max_id), check the per-worker stats in `full_stats/` before trusting it — an aggregation bug once produced a false vocab alarm.

## 4. Launch training

```bash
bash run_full.sh
```

`run_full.sh` does, in order: launch the vLLM extraction server on GPUs 0,1 (data-parallel 2, port 8000), poll `/health` until ready, then launch the 6-rank trainer on GPUs 2-7 and block. `trap cleanup EXIT` kills the server when the trainer exits.

Equivalent individual commands (this is the split form that was actually used, which lets you pause/resume each side independently):

```bash
export PYTHONPATH=/workspace/speculators/.claude/worktrees/lilicorr-minimal/src
export PATH=/workspace/speculators/.venv/bin:$PATH
cd /workspace/speculators/.claude/worktrees/lilicorr-minimal
RUN_DIR=/tmp/lilicorr_check/qwen38-perfectblend/runfull

# extraction server (GPUs 0,1) — run in background
CUDA_VISIBLE_DEVICES=0,1 python scripts/launch_vllm.py /tmp/models/Qwen3.8-27B \
    --target-layer-ids 4 12 20 28 36 44 52 60 \
    -- --data-parallel-size 2 --port 8000 \
    --max-model-len 8448 --max-num-batched-tokens 16384 \
    --gpu-memory-utilization 0.95 --no-enable-prefix-caching \
    > "$RUN_DIR/vllm.log" 2>&1 &

# wait until healthy
until curl -sf http://localhost:8000/health > /dev/null; do sleep 2; done

# trainer (GPUs 2-7)
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True,garbage_collection_threshold:0.6 \
CUDA_VISIBLE_DEVICES=2,3,4,5,6,7 python -m torch.distributed.run \
    --standalone --nproc_per_node 6 \
    -m speculators.train --config full.yaml \
    > "$RUN_DIR/train.log" 2>&1
```

## 6. Resume after a pause

The trainer auto-resumes: `no_resume_from_checkpoint` defaults to false, so re-running the trainer command picks up `save_path/checkpoints/0/` (model + optimizer + scheduler state). Only steps since the last checkpoint are lost (~140 steps on the 2026-10-23 pause). To restart after a full stop:

1. Kill the trainer (and extraction server if also stopping).
2. Relaunch the extraction server (background command above), wait healthy.
3. Re-run the trainer command — it resumes from `checkpoints/0/`.

Checkpoints are written every 5% of an epoch (~4,630 steps, ~10.2 h) into `checkpoints/0/` in place, with an `epoch0_step<N> -> 0` symlink renamed after the write completes; epoch directories appear at epoch boundaries.

## 7. Probe acceptance mid-run

Pause the run (kill trainer, then extraction server — verify with `nvidia-smi` that memory is 0), then serve the current checkpoint on one GPU. `serve_probe.sh` here is the smoke-validation probe (batch metrics grepped from the server log). For per-request JSON metrics — what the numbers below were measured with — add `--per-request-spec-decode-metrics summary`:

```bash
PYTHONPATH=/workspace/vllm/.claude/worktrees/lilicorr-speculators-config \
CUDA_VISIBLE_DEVICES=0 \
/workspace/vllm/.venv/bin/python -m vllm.entrypoints.openai.api_server \
    --model /tmp/models/Qwen3.8-27B --dtype bfloat16 \
    --max-model-len 2048 --max-num-seqs 4 --gpu-memory-utilization 0.95 \
    --port 8002 --per-request-spec-decode-metrics summary \
    --speculative-config '{"method":"dflash","model":"/tmp/lilicorr_check/qwen38-perfectblend/runfull/checkpoints/0","num_speculative_tokens":15,"draft_sample_method":"greedy"}' \
    > /tmp/lilicorr_check/qwen38-perfectblend/runfull/serve_probe.log 2>&1 &

# after /health is up (~230 s):
python probe_acceptance.py   # 16 greedy prompts, saves runfull/acceptance_probe.json
```

KV budget forces `--max-model-len 2048 --max-num-seqs 4` here: one A100 has ~18 GiB free after 55.6 GiB verifier weights + ~4 GiB draft, and the 27B hybrid-mamba KV costs 13.48 GiB per 8192-token request.

## 8. Expected behavior and timing

- ~185k total steps (2 epochs, incl. packing overhead); warmup reaches peak lr 1e-3 around step 7,470 (~16 h), then cosine decay.
- 7.65-8.15 s/step steady state; ~8.3 days/epoch, ~17 days total.
- Trainer memory flat at 42.9-44.6 GiB/GPU (no creep).
- `fetch_frac` ~0.008 steady (extraction on 2 GPUs keeps up easily; demand ~6.0k tok/s vs ~10.2k tok/s the same layout handled in the 4B run).
- Loss (500-step means): 3.74 @ step 500 -> 2.04 @ 5k -> 1.92 @ 8k, through the lr peak with no divergence.
- Val = 1% of rows (~17.4k rows), extraction-bound, ~45 min per epoch.

## Gotchas

- **`/tmp` is ephemeral on this pod.** Checkpoints, data, and logs all live there. Snapshot anything you want to survive a pod restart to `/workspace` — with `cp` (this pod has no rsync; a backup loop once silently no-op'd).
- Use `python -m torch.distributed.run`, not `torchrun`.
- **Extraction server flags are not optional**: `--max-model-len 8448` (the extraction client sends the full untruncated prompt and decodes 1 token, so 8192 exactly would reject all full-length rows) and `--no-enable-prefix-caching` (prefix caching forces the hybrid-mamba "align" mode and fails the KV check).
- `draft_attn_impl: sdpa`: flex attention falls back to dense math inside the dynamo resume frame (anchor selection is `@torch.compiler.disable`), producing 30 GiB score tensors at 1024x16 anchors. SDPA + bool mask is memory-tiled instead.
- `loss_chunk_anchors: 128`: without the chunked checkpointed loss the (anchors\*block, vocab) head tensors peak at 81.5 GiB/GPU and NCCL-kill the run; with it, 46 GiB. Exact loss/grad parity is covered by `tests/unit/models/test_lilicorr.py`.
- The 27B tokenizer is byte-identical to Qwen3.5-4B's, so mask_token_id 248077 (an unused vocab slot) carries over unchanged.
- If the HF cache PVC is full, redirect `HF_DATASETS_CACHE` (and `HF_HUB_CACHE`) to `/tmp` before anything touches the hub.
