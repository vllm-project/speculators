# LiLiCorr

LiLiCorr extends [DFlash](dflash.md) with a candidate-lattice reranker head over the same block-parallel draft backbone. Pure block-parallel drafting decodes every position from its own marginal, so each slot commits its top-1 token independently; the reranker instead scores the top-k candidates per slot jointly with a small transformer and serving commits a whole greedy path through the lattice, so the tokens within a block are chosen consistently with each other. The draft model subclasses DFlash, so the architecture and training pipeline are otherwise unchanged, and it can be paired with any supported verifier. Serving uses vLLM's `lilicorr` method (`"method": "dflash"`, `draft_sample_method: "greedy"` in `--speculative-config`); the full verifier vocabulary is required (vLLM cannot serve a reduced draft vocab for LiLiCorr).

Based on [LiLiCorr: Lossless Lattice Correction for Block-Parallel Speculative Decoding](https://arxiv.org/abs/2608.20530).

## How It Works

### Candidate-Lattice Head

The backbone (DFlash) produces per-slot top-k candidates with their log-probs. A small transformer (default 2 layers, 8 heads) attends over the top-8 lattice at each anchor block and rescores whole candidate paths. Training adds the paper's `base` objective to the DFlash loss:

```
loss = dflash_loss + w_ce * CE + w_pen * penalty
```

Both lattice terms are teacher-forced on the ground-truth predecessor and cover the prefix of slots whose ground truth is in the top-k. They reach the backbone through the candidates' log-probs, the draft hidden states, and the anchor row's features.

### Target Source

By default the CE terms train against the token actually observed at each position (`lilicorr_target_source: input_ids`), matching NVIDIA ModelOpt's reference implementation. Training data generated by sampling (rather than greedy decoding) makes this the correct target: the verifier's own argmax routinely disagrees with the token that was actually sampled. `argmax` scores against the verifier teacher's top-1 token instead.

### Chunked Loss

At scale, the `[anchors*block, vocab]` head tensors dominate GPU memory. `loss_chunk_anchors` computes the draft/verifier head projections and losses in gradient-checkpointed chunks of that many anchor blocks; the chunked loss is exactly equal to the unchunked reduction (covered by unit tests).

## Training

See `examples/train/lilicorr_qwen3_8b_online.sh` for a paper-recipe training example (Qwen3-8B verifier, 5 draft layers, 512 anchors per ~3k-token sequence, fixed-exponential-decay per-position weighting with gamma=7, lr 6e-4, cosine schedule with 4% warmup, base objective with CE/penalty weights 0.25/0.25).

Key LiLiCorr-specific flags:

- `--lilicorr-lr` -- learning rate for the transformer head, separate from the DFlash backbone (defaults to `--lr`)
- `--lilicorr-candidate-topk` -- candidates per slot (power of two, \<= 16; default 8)
- `--loss-chunk-anchors` -- chunk the head projections over this many anchor blocks (see above)
